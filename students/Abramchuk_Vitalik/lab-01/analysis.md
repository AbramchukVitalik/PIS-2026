# Анализ границ ответственности

**Система:** Вариант 16: «Пишем вдвоём» 📝  
**Сценарий:** Создание заметки и совместное редактирование

---

## 1. Транзакционные границы

### 1.1. Где начинается и заканчивается транзакция?

**Начало транзакции:** Пользователь нажимает кнопку "Создать заметку" или "Сохранить изменения" при совместном редактировании.

**Конец транзакции (успешный сценарий):**

- **Основная транзакция БД №1:** Заметка создана + связи с метками
- **Основная транзакция БД №2:** Обновление совместного доступа + история изменений
- **Побочные эффекты (асинхронные):** Push-уведомления другим участникам, обновление кэша, индекс в поисковой системе

**Важно:** Две отдельные транзакции:

1. Создание заметки и связывание с метками - атомарно
2. Обновление истории и совместного доступа - атомарно (может откатиться независимо)

### 1.2. Какие операции должны быть атомарными?

#### Транзакция №1: Создание заметки

**Атомарные операции:**

1. Создание записи Note в таблице `notes`
2. Проверка уникальности заголовка
3. Создание связей Note ↔ Tags
4. Создание initial версии в таблице `note_history`

**Обоснование:** Заметка без версии или без меток может быть некорректной.

#### Транзакция №2: Совместное редактирование

**Атомарные операции:**

1. Проверка доступа участников
2. Создание новой версии заметки в `note_history`
3. Обновление текущего состояния заметки в `notes`
4. Уведомление участников о правках

**Обоснование:** Если версия не сохранилась, участники не должны видеть частично обновленные данные.

### 1.3. Какие операции могут быть асинхронными?

| Операция                          | Обоснование                                        |
| --------------------------------- | -------------------------------------------------- |
| Push-уведомления участникам       | Не критично для сохранения заметки, можно отложить |
| Индексация в поисковой системе    | Best-effort, можно обновить позже                  |
| Обновление кэша последних заметок | Eventual consistency допустима                     |

## 3. Обработка отказов внешних сервисов

### 3.1. Notification Service недоступен

- Таймаут: 5 секунд
- Основная транзакция: НЕ откатывается
- Retry через очередь, exponential backoff
- Компенсация: Нет
- Уведомление пользователя: "Изменения сохранены, уведомления отправятся позже"

### 3.2. База данных недоступна

- Таймаут: 5 секунд для подключения, 30 секунд для запроса
- Основная транзакция: ROLLBACK
- Retry: 3 попытки с экспоненциальной задержкой
- Offline-режим: локальное сохранение в IndexedDB или SQLite
- Уведомление пользователя: "Не удалось сохранить заметку. Попробуйте позже."

### 3.3. Конкурентное редактирование

- Блокировка: `SELECT ... FOR UPDATE` на заметке
- Ролбек транзакции №2 при конфликте
- Retry: пользователь получает уведомление об изменении и может пересмотреть правки

---

## 4. Идемпотентность

- Повторное нажатие "Сохранить": idempotency_key + блокировка кнопки
- Дубли уведомлений: дедупликация по note_id + user_id
- Конфликт версий: проверка последней версии в `note_history`, отклоняем или мержим изменения
