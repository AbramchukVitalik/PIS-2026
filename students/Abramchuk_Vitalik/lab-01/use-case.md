# Use-case: Совместное создание и редактирование заметки «Пишем вдвоём» 📝

**Питч:** Мысли быстрее, чем сообщения.\
**Ядро домена:** Тетради, Заметки, Метки, Совместное редактирование,
История изменений

**Первичный актор:** Пользователь (владелец заметки)

**Вторичные акторы:** - Приглашённый пользователь (соавтор) -
Notification Service (уведомления) - Realtime Sync Service
(синхронизация в реальном времени) - Database (База данных) - Versioning
Service (история изменений)

**Цель:** Создать заметку в тетради и редактировать её совместно с
другим пользователем в реальном времени с сохранением истории изменений.

---

## Предусловия

- Пользователь зарегистрирован и аутентифицирован
- В системе существуют тетради
- Оба пользователя имеют доступ к интернету
- Сервис синхронизации доступен
- База данных доступна

---

## Основной поток (Happy Path)

1.  Пользователь открывает приложение «Пишем вдвоём»
2.  Переходит в нужную тетрадь или создаёт новую
3.  Нажимает «Создать заметку»
4.  Система создаёт пустую заметку со статусом `ACTIVE`
5.  Пользователь вводит заголовок и текст заметки
6.  Система автоматически сохраняет изменения (autosave)
7.  Пользователь нажимает «Пригласить соавтора»
8.  Вводит email второго пользователя
9.  Система отправляет приглашение через Notification Service
10. Второй пользователь принимает приглашение
11. Система открывает доступ к заметке второму пользователю
12. Оба пользователя начинают редактировать заметку одновременно
13. Realtime Sync Service синхронизирует изменения в реальном времени
14. Versioning Service фиксирует каждое изменение как новую версию
15. Пользователь добавляет метки (например: `#идеи`, `#проект`)
16. Система сохраняет метки и связывает их с заметкой
17. Пользователи видят курсоры друг друга и изменения в тексте
18. Пользователь закрывает заметку
19. Система сохраняет финальное состояние
20. Оба пользователя получают уведомление «Изменения сохранены»

---

## Постусловия

- Заметка сохранена в БД
- Заметка связана с тетрадью
- Метки привязаны к заметке
- История изменений доступна
- Оба пользователя имеют доступ к заметке
- Последняя версия заметки сохранена

---

## Альтернативные потоки

### 7a. Пользователь хочет сделать заметку публичной по ссылке

1.  Пользователь нажимает «Поделиться по ссылке»
2.  Система генерирует уникальный URL
3.  Любой пользователь с ссылкой получает доступ на чтение
4.  Возврат к основному потоку

### 15a. Пользователь хочет отфильтровать заметки по метке

1.  Пользователь нажимает на метку `#проект`
2.  Система отображает все заметки с этой меткой
3.  Пользователь открывает нужную заметку

### 3a. Пользователь хочет создать заметку из шаблона

1.  Пользователь выбирает «Создать из шаблона»
2.  Система отображает список шаблонов
3.  Пользователь выбирает шаблон
4.  Система создаёт заметку с предзаполненным текстом
5.  Возврат к основному потоку

---

## Исключительные ситуации

### Пользователь не найден по email

- Система показывает сообщение «Пользователь с таким email не найден»
- Предлагает отправить приглашение на регистрацию

### Потеря соединения во время редактирования

- Система переходит в Offline-режим
- Изменения сохраняются локально
- После восстановления соединения выполняется синхронизация

### Конфликт редактирования одного фрагмента

- Система создаёт две версии фрагмента
- Пользователю предлагается объединить изменения вручную

### Ошибка автосохранения

- Данные сохраняются в локальный кэш
- После восстановления соединения отправляются в БД

### Notification Service недоступен

- Уведомление ставится в очередь для повторной отправки

---

## Критические требования

- Realtime синхронизация \< 200 мс
- Autosave каждые 2 секунды
- Поддержка Offline-режима
- Хранение истории версий
- Логирование всех изменений
